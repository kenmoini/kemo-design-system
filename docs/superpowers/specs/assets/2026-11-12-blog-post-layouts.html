How we cut cold-start time for cluster consoles by 62%

A year of profiling, one embarrassing N+1 against the API server, and the caching layer we should have built first.

Priya Raman · 11 Nov 2026 · 9 min read

Opening a cluster in Kemo Console used to take a little over four seconds on a cold cache. For a page people open forty times a day, that is a long time to look at a skeleton.

Where the time went

We traced a thousand cold loads. The surprise was not the bundle, it was /api/resources: one request per resource kind, in sequence.

# before: 38 sequential discovery calls
for kind in kinds: client.list(kind, limit=1)
# after: one aggregated discovery document, cached per cluster
doc = discovery.aggregated(cluster, ttl="10m")
The fastest request is the one the browser already has the answer to.
4.1s → 1.6sp50 cold start
38 → 1discovery requests
−62%time to interactive
NoteAggregated discovery needs Kubernetes 1.30 or newer. Older clusters fall back to the batched path.
