# Known-issues cleanup Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Close every item in `docs/known-issues.md` that has an easy, cheap fix, area by area, removing each fixed row from that document as it lands.

**Architecture:** No new features. Each task is a batch of small, independent edits in one area (forum, blog, deployments, access, status, dashboard and shell, auth, tooling, Park UI quirks). Every item keeps or adds a covering test. The inventory `docs/known-issues.md` is the requirements document: each task names its row ids, and the implementer deletes those rows in the same commit.

**Tech Stack:** React 19, Park UI (Ark UI 5.40) on Panda CSS 2.5, Vitest + Testing Library, Playwright, Next.js 16. No new dependencies.

**Spec:** `docs/known-issues.md` (the row ids below refer to it). The phase specs under `docs/superpowers/specs/` remain the authority for behaviour; a fix must not change a behaviour a spec pins.

## Global Constraints

- Inside `packages/ui/src/**`, styled-system imports are relative (`../../../styled-system/*` from a page family, one more `../` inside a variation folder) and Park components come from `components/ui`; never `~/` or bare `styled-system/`. Tokens only; no raw colour values. Surfaces `canvas`, `gray.surface.bg`, hairlines `border`.
- Synced Park files (`src/components/ui/**` except `password-input.tsx`, `src/theme/recipes/**`, `src/theme/colors/**`, `global-css.ts`, `conditions.ts`, `text-styles.ts`) are never hand-edited; an upstream quirk is fixed by a port transform in `scripts/park-ui/` or a local override.
- `'use client'` where hooks are used. Prettier `semi: false, singleQuote: true, printWidth: 100, trailingComma: 'all'`; ESLint zero warnings (static style props; `cva` for variants).
- A live region that must announce repeatedly is a persistent element whose text changes, never an element mounted with its text.
- Every visible control does something; a control whose callback is absent is not rendered.
- Each task removes the rows it fixes from `docs/known-issues.md` (and nothing else there) in its commit. Row ids are stable; do not renumber.
- Stage by explicit path only (never `git add -A` / `git add .`). One commit per task on `main`; do not push. Green before every commit: `pnpm --filter @kemo/ui lib && pnpm test && pnpm typecheck && pnpm lint && pnpm format:check`. Tasks that touch the preview's routes or e2e also build and run Playwright on :3100 (sandbox disabled); the owner's `next dev` on :3000 is never stopped or reused.

## Review Focus

1. A status region that announced once must announce again on the next event (F11, B4): tests post twice and assert the text is present both times.
2. A fix must not change what a spec pins: the reviewer compares each changed behaviour against the phase spec named in the row.
3. Removing an export must not break a consumer: `pnpm typecheck` covers the preview; the reviewer greps the repo for the removed names.
4. Port transforms must be idempotent: running `pnpm park-ui port` twice yields no diff (T-tasks test it).
5. A focus move must land on an element that exists after the update (F13, B6): tests assert `document.activeElement`.
